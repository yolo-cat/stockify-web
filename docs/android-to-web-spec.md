### 1.3 Group Summaries
- **`database_entities_and_settings`**: This module group defines the Room SQLite persistence layer (AppDatabase v20 with Stock, StockTransaction, StockHistoryPrice, and Account), reactive repository/DAO contracts (StockDao, StockRepository, TransactionListRepository), and Preferences DataStore (SettingsDataStore) for user preferences, asset balances (BankDeposit, Loan), and local caches. It also establishes core market/currency normalization, rounding, text scaling, and account fee/restore validation utilities. For Web v1 on Lovable Cloud, these structures map to user-scoped Supabase PostgreSQL tables protected by RLS (auth.uid() = user_id), with App Lock PIN and Google Drive metadata excluded.
- **`core_holdings_and_pl_engine`**: `core_holdings_and_pl_engine` implements Stockify's pure-Kotlin portfolio accounting, position validation, and return calculation engine. It handles chronological transaction replay scoped by `(market, stockCode, accountId)` with valuation-date cutoffs, pre-write balance and corporate-action validation, moving-average realized/unrealized P&L decomposition (preserving legacy total P&L), DST-aware XIRR cash-flow solving, stock-dividend/sell-fee helpers, per-stock calculation caching, and market/share formatting. All types are pure in-memory computation primitives with zero database or network dependencies, mapping cleanly to TypeScript `src/domain/**` for Web v1.
- **`margin_and_short_selling`**: The `margin_and_short_selling` module group implements Taiwan-only margin buying ('融資買進'), margin repayment ('融資還款' or '賣出' repayment), short selling ('融券賣出'), short covering ('買券還券'), and short compensation ('融券補償') via deterministic chronological replay scoped by (market, stockCode, accountId, lotId). `MarginCalculationSupport` and `ShortSellingCalculationSupport` provide both single-shot calculation and incremental monotonic `HistoricalTimeline` / `HistoricalXirrTimeline` evaluators for daily simple interest/borrow-fee accrual, corporate-action share adjustments, and XIRR cash-flow generation. `FinancingTransactionValidationSupport` enforces market restrictions, non-negative/finite bounds, per-type field exclusivity, and strict lot balance invariants before persistence.
- **`history_chart_and_calendar`**: The `history_chart_and_calendar` group implements incremental transaction replay (`HistoricalLongPositionTimeline`, `HistoricalTransactionCashFlowTimeline`) for multi-date portfolio/stock history chart valuation and historical XIRR cash flows, alongside market-timezone/coverage helpers (`HistoryChartCalculationSupport`), generation-guarded monthly history caching/progress tracking (`StockHistoryCache`, `PortfolioHistoryProgressTracker`), and the `PerformanceCalendarCalculationSupport` calculator that derives daily and monthly P&L and compounded return percentages strictly from replayed `PersonalHistoryPoint` data.
- **`market_data_and_edge_apis`**: This group implements realtime stock quote polling, multi-market historical price retrieval, TWSE weighted index and USD/TWD exchange rate updates, Taiwan holiday calendar caching, TW/US stock master list synchronization, Yahoo dividend scraping, and reactive portfolio aggregation (`OfflineStockRepository`). External data sources use a strict primary + single-fallback strategy with shared concurrency semaphores (`MAX_PARALLEL_STOCK_REQUESTS = 3`), transient network retries, strict TLS validation, and incremental StateFlow publishing. In `stockify-web`, all external market, FX, calendar, stock list, and dividend endpoints are proxied through Supabase Edge Functions (`supabase/functions/*`) while user preferences and portfolio persistence use RLS-protected PostgreSQL tables.
- **`import_export_and_backup`**: The `import_export_and_backup` group implements local CSV transaction export/import (`CsvService`), deduplication with legacy market repair (`CsvTransactionDedupSupport`), asset-balance JSON backup (`AssetBalanceBackupCodec`), and holdings display-order backup (`HoldingsOrderBackupService`). `CsvService` exports 46-column UTF-8 BOM CSVs and imports multi-encoding streams (`UTF-8` BOM / `UTF-16LE` BOM / `UTF-16BE` BOM / strict `UTF-8` with `Big5` fallback) with multiline quoted record parsing and provisional ID sequencing for chronological replay validation. `AssetBalanceBackupCodec` enforces strict schema (`stockify.asset-balances` v1), 2 MiB size bounds, 10,000-row limits, and non-negative finite-sum invariants for bank deposits and loans, while `HoldingsOrderBackupService` supports JSON (`version = 1`) and legacy newline-delimited holdings order files. View-model support functions format CSV row error context, compute minimal existing transaction keys to fetch for import validation/dedup, handle replacement-restore account fallbacks, and escape SQLite `LIKE` wildcards.
- **`ui_screens_viewmodels_and_navigation`**: The UI, ViewModel, and navigation layer implements an MVVM Compose architecture with a single-activity NavHost (`MainActivity` + `NavGraph` + `Screen`) and 5 bottom navigation destinations (`Holdings`, `Transactions`, `AddTransaction`, `DataManagement`, `Settings`) plus secondary detail routes (`StockDetail`, `TransactionDetail`, `AssetOverview`, `DividendInfo`, `YahooQuote`). ViewModels (`HoldingsViewModel`, `StockDetailViewModel`, `TransactionsViewModel`, `AddTransactionViewModel`, `TransactionDetailViewModel`, `AssetOverviewViewModel`, `DividendInfoViewModel`, `SettingsViewModel`) compose reactive `StateFlow` pipelines from Room DAOs, DataStore preferences, market services, and pure calculation helpers, offloading XIRR and historical replay to `Dispatchers.Default`. All transaction mutations, CSV restores, and asset-balance operations run full timeline/codec validation before committing atomically, while Web v1 replaces Room/Google Drive with Supabase PostgreSQL (RLS `user_id`) and Edge Functions and excludes App Lock and PDF import.

### 3.2 `core_holdings_and_pl_engine`
- Chronological transaction ordering & valuation cutoff (HoldingCalculationSupport.kt:31-42, 48-65): transactions are filtered by `date <= valuationDate` and sorted ascending by `(date, recordTime, id)`. When `transactionsAreOrdered = true`, the caller guarantees ascending `(date, recordTime, id)` order and the fast path skips re-sorting while preserving identical results.
- Long position replay rules (HoldingCalculationSupport.kt:48-109): replays per `PositionKey(StockMarket.normalize(market), stockCode, accountId)`. `"買進"`/`"融資買進"` add `buyShares` to `shares` and `buySharesTotal`, and add `expense` to `totalBuyExpense` and `buyCostTotal`. `"賣出"` subtracts `sellShares` from `shares`, adds `sellShares` to `sellSharesTotal`, `sellPrice * sellShares` to `sellAmountBeforeFee`, and `income` to `totalSellIncome` and `totalSellNetIncome`. `"配股"` adds `dividendShares` to `shares`. `"配息"` adds `resolveDividendIncome(tx)` to `totalDividendIncome`. `"減資"` adds `capitalReductionShareChange` to `shares` and `cashReturned` to `totalSellIncome`. `"分割"` adds `splitShareChange` to `shares` and multiplies `buySharesTotal` and `sellSharesTotal` by `splitShareFactor`. Final `shares` is clamped via `coerceAtLeast(0.0)`.
- Pre-write long balance & corporate action validation (HoldingCalculationSupport.kt:120-217, 329): `POSITION_EPSILON = 1e-6`. Replays all transactions sorted by `(date, recordTime, id)` per `(market, stockCode, accountId)`. `"賣出"` rejects `!sellShares.isFinite() || sellShares < 0.0` and overselling (`currentShares + 1e-6 < sellShares`). `"減資"`/`"分割"` reject negative recorded before/after shares, reject partial recording (`hasRecordedBefore != hasRecordedAfter`), allow legacy ratio-only rows (both `0.0`), and require `recordedBefore == currentShares` and `recordedAfter == expectedAfter` within tolerance `max(1e-6, max(abs(left), abs(right)) * 1e-9)`. Post-step `nextShares` must be finite and `>= -1e-6`.
- Split & capital reduction share formulas (HoldingCalculationSupport.kt:224-261): `splitShareChange` uses `sharesBefore = sharesBeforeSplit > 0 ? sharesBeforeSplit : currentShares` and `sharesAfter = sharesAfterSplit > 0 ? sharesAfterSplit : sharesBefore * (stockSplitRatio > 0 ? stockSplitRatio : 1.0)`, returning `sharesAfter - sharesBefore`; `splitShareFactor` prefers `sharesAfterSplit / sharesBeforeSplit` when both `> 0`, else `stockSplitRatio > 0`, else `1.0`. `capitalReductionShareChange` uses `sharesBefore = sharesBeforeReduction > 0 ? sharesBeforeReduction : currentShares` and `sharesAfter = sharesAfterReduction > 0 ? sharesAfterReduction : sharesBefore * (1.0 - capitalReductionRatio / 100.0)`, returning `sharesAfter - sharesBefore`; `capitalReductionShareFactor` prefers `sharesAfterReduction / sharesBeforeReduction` when both `> 0`, else `1.0 - capitalReductionRatio / 100.0` when `capitalReductionRatio in 0.0..100.0`, else `1.0`.
- Dividend income resolution & cost basis formulas (HoldingCalculationSupport.kt:263-327): `resolveDividendIncome` returns `dividendIncome` if `dividendIncome != 0.0 || income == 0.0`, else falls back to legacy `income`. `performanceCostBasis = totalBuyExpense - totalSellIncome - (if (excludeDividendIncome) 0.0 else totalDividendIncome)`. `performanceMarginCashBalance = cashBalance - (if (excludeDividendIncome) totalDividendIncome else 0.0)`. `remainingPositionDenominator` returns `costBasis` if `shares > 0.0 && costBasis > 0.0`, else `totalInvestment`. `positionInvestmentBasis` sets `cumulative = longInvestment + shortCumulativeInvestment`; if closed (`shares <= 1e-6 && marginDebt <= 1e-6 && shortOutstandingShares <= 1e-6`), `remaining = cumulative`; otherwise `longRemaining` prefers `financedRemainingInvestment` (`> 1e-6`, fallback `longInvestment`) when financed, else `costBasis` (`shares > 1e-6 && costBasis > 0`), else `longInvestment`, else `0.0`, and `remaining = longRemaining + shortRemainingInvestment`.
- Open position filter (OpenPositionSupport.kt:3-34): `OPEN_POSITION_EPSILON = 1e-6`. A `market:code` key is open at `valuationDate` iff `longSummary.shares > 1e-6`, OR `marginSummary.outstandingPrincipal > 1e-6 || marginSummary.accruedInterest > 1e-6`, OR `shortSummary.outstandingShares > 1e-6`.
- Moving-average realized/unrealized P&L breakdown (ProfitLossBreakdownSupport.kt:39-285): `unrealizedProfitLoss = legacyTotalProfitLoss - realizedProfitLoss` guarantees exact preservation of total P&L. Buys (`"買進"`, `"融資買進"`) add `buyShares.coerceAtLeast(0.0)` and `expense` per `(market, stockCode, accountId)`. Sells (`"賣出"`) dispose `min(sellShares, max(longState.shares, 0.0))` at `averageCost = longState.cost / longState.shares`, realizing `allocatedIncome - disposedCost` and reducing `longState.shares` and `longState.cost`. `"配股"` adds `dividendShares` at 0 cost. `"配息"` realizes `resolveDividendIncome` only when `includeDividendIncome == true`. `"減資"` with `cashReturned > 1e-6 && shareChange < -1e-6` removes `removedCost = averageCost * min(-shareChange, longState.shares)` and realizes `cashReturned - removedCost`; loss reduction (`cashReturned <= 1e-6`) reduces shares without removing cost or realizing loss. `"分割"`/`"減資"` scale matching short lots' `originalShares` and `remainingShares` by factor. Short lots (`lotId` fallback `"legacy-short-${id}"`) accrue daily simple borrow fee `remainingPrincipal * annualRate / 100.0 * days / denominator` (`360` or `365`, `days = ChronoUnit.DAYS.between(startDate, endDate).coerceAtLeast(0L)`) before each event and at `valuationDate`; cover allocates `feeAllocation`, `openingIncome`, `coverExpense`, and `coveredPrincipal` proportionally and realizes `openingIncome - coverExpense - feeAllocation`. `"融券補償"` subtracts `shortCompensation` from `realizedProfitLoss`. `marginSummary.actualInterestPaid > 1e-6` is subtracted from `realizedProfitLoss`.
- XIRR calculation & convergence rules (ReturnRateCalculator.kt:20-142): filters cash flows with `abs(amount) > 1e-10`, sorts by `dateMillis` ascending; returns `null` if `< 2` flows or lacking both positive and negative flows. Converts timestamps to calendar days in `zoneId` via `LocalDate` + `ChronoUnit.DAYS.between` / `365.0` (DST-safe). Solves via Newton-Raphson (`DEFAULT_GUESS = 0.1`, max 100 iterations, tolerance `|xnpv| < 1e-8` or `|nextRate - rate| < 1e-10`, requiring `rate > -0.999999999` and `|derivative| >= 1e-10`), falling back to Bisection (`lower = -0.999999999`, `upper = 0.1` expanded up to 80 times via `< 1.0 ? upper + 1.0 : upper * 2.0`, then max 200 bisection steps to `|midValue| < 1e-8` or `|upper - lower| < 1e-10`). `calculateXirrPercentage` returns `xirrRate * 100.0`.
- Stock dividend conversion (StockDividendCalculationSupport.kt:3-21): `TAIWAN_STOCK_PAR_VALUE = 10.0`. Taiwan stock dividend shares = `exRightsShares * (stockDividend / 10.0)`; US stock dividend shares = `exRightsShares * stockDividend`.
- Taiwan minimum sell fee rule (TransactionCostSupport.kt:3-11): returns `minFeeRegular` when `shares % 1_000.0 == 0.0` (round lot), else `minFeeOddLot` (odd lot).
- Date-only replay cutoff & zone mapping (TransactionDateSupport.kt:15-41): `replayCutoffMillis(isoDate, storageZoneId)` parses strict `ISO_LOCAL_DATE` and returns `(date.plusDays(1).atStartOfDay(storageZoneId).toInstant().toEpochMilli()) - 1L` (preserving exact DST day boundaries); returns `null` on invalid ISO date. `moveToZoneDateStartMillis` extracts `LocalDate` in `storageZoneId` and returns `date.atStartOfDay(targetZoneId).toInstant().toEpochMilli()`.

Cash dividend net income auto-calculates `grossAmount = roundCalculatedCurrency(pps * s, market)` and `netAmount = roundCalculatedCurrency((grossAmount - feeAmount - premiumAmount).coerceAtLeast(0.0), market)` (AddTransactionScreen.kt:517-527; AddTransactionViewModel.kt:635).
- Margin self-funded auto-fill & repayment validation (`TransactionFormSupport.kt`): `autoCalculatedMarginSelfFundedText(expense, marginPrincipalText)` returns `expense - principal` (plain BigDecimal) only when `principal >= 0`, `expense >= 0`, and `selfFunded >= 0`, else `""`; manual override flag is true only when input `isNotBlank()` (AddTransactionScreen.kt:858-861). `isValidMarginRepaymentAmounts` requires both values finite `>= 0.0`, `(repayment > 0.0 || actualInterest > 0.0)`, and `repayment <= remainingPrincipal`. `resolveSellMarginRepayment` defaults to `sellIncome` only when `repaymentText.isBlank()` (TransactionFormSupport.kt:11-29,67-79).
